Drop a folder.

Import a folder by dropping it onto the Library source area. Reuse the import engine that Settings already uses.

Scope: plan for review. App code has not been changed.

Behavior · Files · Flow · Pseudocode · Verification

1. User behavior

  • Drop a folder onto the Library grid or its empty state. Its top folder becomes a collection; supported files and subfolders keep their nesting.
  • An unzipped Mado export uses its top-level library.json. Keep ids and metadata; skip ids already present, including trash. A broken manifest follows the existing plain-folder rule.
  • Loose images and videos keep the current add-source behavior. Multiple folders import one at a time, each with its own manifest scope. Mixed drops add loose media separately and import each folder.
  • Keep the existing Library drop surface. Collection cards and collection pages keep their current behavior; importing a folder into an existing collection is outside this change.
  • Use neutral Library feedback: “Drop files or folders into Library”. Do not describe a folder count as a file count. Keep the current size limit hint and visual treatment.
  • After release, show “Reading folder…” while scanning, then “Importing file N of M…” in a small Library status area with a progressbar and polite live status. Progress also stays visible in Settings. Completion and errors use existing import toasts.
  • Reject a new folder drop while an import or export is running. Keep handling the event so the browser does not open the dropped item. Show a short “Wait for the current import or export to finish.” message.
  • On a folder-read error, save nothing from that folder and show a clear error. Continue with other dropped roots. If folder reading is unavailable, direct users to Settings → Data → Import a folder; do not silently flatten it.

Existing rules stay in force: hidden files are quiet skips; unsupported, empty, or over-512-MB files are counted skips; folders with no supported media create nothing; empty folders are not saved; plain-folder imports can create duplicates; no zip support or cancel button.

4. Data flow

Library native drop
  → capture roots synchronously (before await)
  → directory roots: walk entries → ImportFile[] per root
      → importLibraryFiles → buildImportPlan
      → collections → sources → IndexedDB + OPFS
      → compression → refresh sources + collections
  → loose files: existing source validation → useCreateSources
  → shared progress and existing result toasts

5. Control flow

  1. Only enable the interceptor on the Library source area. It must run before react-dropzone flattens files or filters out library.json.
  2. Capture file entries and loose Files in the native drop call stack. If there are no directory roots, return false and let the normal handler run.
  3. For a directory drop, prevent default, consume the event and acquire the shared import/export lock before any await. Reject busy drops immediately.
  4. Run the entire folder batch inside the import mutation, so navigation and Settings closure do not cancel its callbacks. Read each root completely before writing it.
  5. Read directories in batches until an empty batch. Use explicit paths such as Moodboard/Colors/blue.png. Read sequentially to avoid thousands of concurrent promises; do not load file bytes into memory.
  6. Import each root separately. Never combine two exports into one manifest lookup. Skip unreadable roots with a clear error. A full disk stops the remaining batch.
  7. Refresh caches after any writes, including partial failure. Release the lock and clear activity in a final cleanup. Both Settings and Library observe the same activity.

The lock is per browser tab, matching current activity tracking. Cross-tab coordination is outside this change.

6. Pseudocode

Signatures are proposed; use existing DOM entry types where TypeScript provides them. 

captureImportDrop(dataTransfer):
  synchronously map file items to getAsEntry/webkitGetAsEntry results
  capture loose Files now too
  return roots; mark unavailable directory reading explicitly

readImportDropFolder(root):
  files = []
  await walkImportEntry(root.entry, root.name, files)
  return files

walkImportEntry(entry, path, files):
  if hidden path: return
  if file:
    files.push({ path, file: await readImportEntryFile(entry) })
    return
  reader = entry.createReader()
  repeat:
    batch = await readImportEntries(reader)
    if batch is empty: return
    for child in batch:
      await walkImportEntry(child, path + '/' + child.name, files)

readImportEntries(reader):
  wrap reader.readEntries(success, failure) in Promise

readImportEntryFile(entry):
  wrap entry.file(success, failure) in Promise

importLibrary(pickedFiles, onProgress):
  return importLibraryFiles(pickedFiles.map(toImportFile), onProgress)

importLibraryFiles(files, onProgress):
  run existing manifest → plan → collections → sequential saves
  return existing ImportResult

tryStartImportOperation(kind):
  if active operation exists: return false
  set active kind synchronously; return true

finishImportOperation():
  clear active operation

useImportLibrary():
  startImport(files) / startDroppedImport(roots):
    if lock unavailable: toast busy; return
    start existing mutation with ImportRequest
  mutation:
    picked input → importLibrary
    dropped input → for each directory root:
      publish reading activity
      read folder; on read error toast and continue
      publish importing activity
      importLibraryFiles; enqueue saved plain-folder sources
      show existing per-root result toast
      on quota error: stop batch
  onSettled:
    clear progress, release lock, invalidate affected caches

useExportLibrary().startExport():
  if lock unavailable: toast busy; return
  start existing export mutation immediately
  onSettled: clear export progress; release lock

useImportDrop(onLooseFiles):
  handleFolderDrop(event):
    roots = captureImportDrop(event.dataTransfer)
    if no directories and not an unsupported folder: return false
    prevent default; stop propagation
    if unsupported: show Settings fallback; return true
    if busy: show busy toast; return true
    startDroppedImport(directory roots)
    onLooseFiles(loose files, using existing validation)
    return true

useSourceDropzone(collectionId, optionalInterceptor):
  root onDrop(event):
    clear drag feedback
    if optionalInterceptor(event) consumed: stop default extraction
    otherwise let existing react-dropzone onDrop add files

SourceDropZone(props):
  useSourceDropzone(collectionId, props.interceptor)
  render existing wrapper and overlay with Library-specific copy

Library():
  connect createSources callback to useImportDrop
  render SourceDropZone with interceptor
  render LibraryImportStatus(shared activity)

LibraryImportStatus(activity):
  if idle: return null
  render polite reading text, or labelled progressbar + import text
