1. Data model NEW

// features/sources/text-source.type.ts
export type TextSourceContent = {
  body: string;                      // the whole file, ≤ 1 MB
  format: 'markdown' | 'plain';
  fileName: string;                  // "brief.md", for download and export
};

// source-types.ts
Source.kind: 'image' | 'video' | 'website' | 'text'
Source.text?: TextSourceContent      // only on text sources, like `site`

// For website AND text, the media fields describe the thumbnail:
storageKey, fileName, mimeType, sizeBytes, width, height, durationSeconds
// null / '' / 0 when there is no thumbnail.

Why the text lives in IndexedDB

  • One file slot per source. The thumbnail needs storageKey. Putting the text in the record keeps one OPFS file per source, so delete, trash, compression and replace do not need a second key.
  • Same shape as websites. “Content in the record, optional thumbnail in OPFS” is already how websites work. Card, panel and replace can share that path.
  • The card shows its text at once. No async file read, so the card has its final height on first paint. That matters because masonry-layout measures card heights.
  • Search can read it later with no extra copy. This answers the roadmap open question “where text sources live”.
  • It fits the cloud plan. Phase 3 uses Postgres (Neon) for records and R2 for media. When a source is uploaded, the text goes into a Postgres text column with the rest of the record, and only the thumbnail goes to R2. Postgres can search that column, and a 1 MB value is fine there. If the text were in OPFS, the upload would have to send it to R2 first and then read it back to search it.
  • Cost: 1 MB per text in IndexedDB is fine. No DATABASE_VERSION bump, because no store or index changes. text is a new optional field, like site.

2. User behavior

Adding

  • Drop, pick, paste a file, or import a folder: .txt, .md, .markdown become text sources. The kind is chosen by MIME type, then by file extension, because many systems give .md an empty type.
  • Other text/* files (HTML, CSV, code) are still rejected.
  • Limit is 1 MB for text (about 500 pages), not 512 MB. Too big shows the usual reject toast.
  • Files are read as UTF-8. Name = file name without the extension. No thumbnail at first.

Card NEW

  • Like mymind: a soft card with only the first sentence in a serif font, at most 4 lines with “…”. No icon and no label.
  • No fixed shape. The height follows the text, so a short note is a short card.
  • The first sentence is the first Markdown heading, or else the first sentence of the first line that has words. Markdown signs (#, **, [](), list dashes) are removed. If nothing is left, the source name is shown.
  • With a thumbnail: the image or video sits under the text, inset by 8 px on the sides and bottom. The inner corner is the outer radius minus 8 px, so the corners stay parallel, like the Focus Frame logo. The thumbnail keeps its own aspect ratio.
  • A video thumbnail plays when half of it is on screen, like video cards. Far cards unmount it.

Thumbnails for text and websites NEW

  • A text source can get a thumbnail: image or video. Use the same ways as website thumbnails: the panel thumbnail, the toolbar, or a drop on the viewer.
  • Embeddable website thumbnails now also accept video. Today they allow only images.
  • A text source never changes kind on replace:
    • An image or video sets the thumbnail.
    • A .md/.txt replaces the text. Name, note, link and collections stay.
  • Thumbnails are compressed like other media: images to WebP, videos with mediabunny.
  • Websites that cannot be embedded keep today’s rule: a dropped file turns them into an image or video source.
  • Removing a thumbnail is not part of this plan. Replacing it works.

Detail dialog

  • The viewer shows a paper sheet about 70 characters wide that scrolls. Headings use the same serif as the card. .md is drawn with GFM (tables, task lists, code). .txt keeps its line breaks.
  • Safe by default: raw HTML is shown as text, never run. Links open in a new tab with rel="noreferrer". Remote images are not loaded; they show as links with their alt text. Loading them would tell other servers what the user opened.
  • The panel shows the thumbnail, like websites. It plays a video thumbnail muted and looping. Info line: Markdown · 12 KB.
  • Download gives the text file, built from the record. It does not give the thumbnail.

Export and import

Short version here. Details and tests are in Export & import.

Export & import with text NEW

Today export and import know only images, videos and websites. Three places would break a text source without changes:

Place Today What breaks
export-manifest.ts kind: z.enum(['image','video','website']), role: z.enum(['media','shortcut']) A library.json with a text source fails to parse. Import then falls back to the plain-folder rule, and every id and nesting is lost.
export-layout.ts toSourceFiles Writes only shortcut and media The text body is never written. The export loses it.
import-plan.ts toManifestPlan if (!file && kind !== 'website') skip A text source with no thumbnail has no media file, so it is skipped.

Design

  • The .md/.txt file is the truth. Export writes the body as a file with the new role 'text'. library.json stores only text: { format, fileName }, not the body, so the text is not saved twice. If a user edits brief.md in the unzipped folder, import picks up that edit.
  • File names: the text file uses the source name plus the original extension: Brand brief.md. A thumbnail uses the same name with its own extension: Brand brief.webp. The existing name registry already keeps names unique in each folder.
  • Import: findTextFile finds the 'text' file, like findMediaFile. A text record with no text file is skipped and counted. A missing thumbnail only drops the thumbnail, like websites.
  • buildImportPlan stays pure and does not read files. The record item carries textFile, and import-actions reads textFile.text() just before it saves. A body that is empty or over 1 MB is skipped.
  • EXPORT_MANIFEST_VERSION goes up by one. A new export opened in an old Mado fails the manifest parse and falls back to a plain-folder import. That is the expected behavior for a newer format. Old exports still import with no change.
  • Plain folder import: .md, .markdown and .txt become text sources through createSource. Other text files are counted as skipped.

4. FLIP for text and websites NEW

Today only image and video fly; text and websites just fade. The existing flipSourceDetail already works for any element: it scales the viewer element by one number until it covers the card, then uses clip-path to cut it to the card’s shape. Images and videos pass their aspect ratio. Text and websites pass null, so the whole element box is used.

Text
fly the sheet. Anchor the top, so the serif first line on the card turns into the serif heading.
→
Website (embedded)
fly the frame. Until the iframe loads, the frame shows the thumbnail, so the flight carries the picture and not an empty box.
→
Website (not embedded)
fly the image or video, the same as an image source.
  • flipSourceDetail gets an anchor: 'center' | 'top' option. Today the origin is the center. For a tall sheet, a centered flight would show the middle of the text in the card, and the card shows the start.
  • The frame waits for the iframe’s onLoad. Then it crossfades from the thumbnail to the live page. A website with no thumbnail flies a plain muted box.
  • The same rules stay: only the first source after opening flies, arrow keys swap without it, close shrinks back into the card, and reduced motion or no card on screen means a plain fade.
  • Spec: replace “With no card on screen, a website, or reduced motion on, the dialog just fades” with the new rule.

5. Should people edit text in Mado?

My pick is still option B, plain edit. With the text in IndexedDB it is even smaller now: Save is one record update, not a file replace. It is the last step, so it can be cut.

Your call. Nothing else in the plan depends on it.

A · Read only

  • To change the text, edit it elsewhere and drop the file again.
  • Cheapest, but fixing one typo in a brief means leaving Mado.

B · Plain edit ✓

  • Edit (or E) turns the sheet into a text box with the raw text. Save with ⌘/Ctrl+S, or Cancel.
  • Save calls updateSourceText, one IndexedDB write.
  • With unsaved changes, close, Cancel and the arrow keys ask “Discard your changes?”.

C · Rich editor

  • Tiptap or Milkdown. A big new dependency.
  • Turning the page back into Markdown can change the user’s file.

Rules for B: empty text cannot be saved. Over 1 MB shows an error. Name, note, link and collections never change. A save error keeps the draft and shows a toast. Two tabs: the last save wins.

9. Control flow

detectFileKind(file)
  image/* → image · video/* → video
  mime in TEXT_FILE_TYPES, or empty mime + .txt/.md/.markdown → text
  else → null

replaceSourceFile(source, file)
  source text   + text file     → replaceSourceText (body, format, fileName)
  source text   + image/video   → thumbnail, kind stays text
  embedded site + image/video   → thumbnail, kind stays website
  other site    + image/video   → becomes image/video (today's rule)
  image/video   + text file     → rejected: "Drop an image or video."

toTextCardTitle(text, fallback)
  first ATX heading → else first line with words → cut at first . ! ? → strip Markdown
  → trim to 200 chars → empty ? fallback : title

10. Pseudocode

// source-media.ts
export function detectFileKind(file: File): 'image' | 'video' | 'text' | null {
  const [group] = file.type.split('/');
  if (group === 'image' || group === 'video') return group;
  if (TEXT_FILE_TYPES.mime.includes(file.type)) return 'text';
  if (!file.type && TEXT_FILE_TYPES.ext.includes(extensionOf(file.name))) return 'text';
  return null;
}

// source-actions.ts
export async function createSource(input) {
  const { file, … } = newSourceSchema.parse(input);
  const kind = detectFileKind(file);
  if (kind === null) throw new Error('Only images, videos and text are supported');
  if (kind === 'text') return createTextSource({ … });
  … // unchanged
}

// *** createTextSource ***
async function createTextSource({ collectionId, file, name }) {
  const body = await file.text();
  const source: Source = {
    …baseFields, kind: 'text',
    text: { body, format: isMarkdown(file) ? 'markdown' : 'plain', fileName: file.name },
    fileName: '', mimeType: '', sizeBytes: 0, ...UNKNOWN_METADATA, storageKey: null,
  };
  await putSource(source);
  return source;
}

export async function updateSourceText(id: string, body: string): Promise<Source> {
  const parsed = textBodySchema.parse(body);          // not empty, ≤ 1 MB
  return updateRecord(id, (current) => {
    if (current.kind !== 'text' || !current.text) throw new Error('Not a text source.');
    return { ...current, text: { ...current.text, body: parsed }, updatedAt: now() };
  });
}

// *** toReplacementKind ***
function toReplacementKind(current, kind: 'image' | 'video'): SourceKind {
  if (current.kind === 'text') return 'text';
  if (canEmbedSite(current)) return 'website';     // image or video now
  return kind;
}

// text-source.ts
export function toTextCardTitle(text: TextSourceContent, fallback: string): string {
  const lines = text.body.split('\n').map((line) => line.trim()).filter(Boolean);
  const heading = text.format === 'markdown' ? lines.find((l) => /^#{1,6}\s/.test(l)) : undefined;
  const line = heading ?? lines[0] ?? '';
  const sentence = heading ? line : (line.match(/^.+?[.!?](\s|$)/)?.[0] ?? line);
  const plain = stripMarkdown(sentence).slice(0, 200).trim();
  return plain || fallback;
}

// source-card.tsx
function SourceCardTextTile({ source, isNear }) {
  return (
    <div className="rounded-xl bg-muted p-4 [&:has([data-thumb])]:pb-2">
      <p className="line-clamp-4 font-serif text-xl/tight">
        {toTextCardTitle(source.text!, source.name)}
      </p>
      {source.storageKey && (
        <div data-thumb className="-mx-2 mt-3 overflow-hidden rounded-[4px]"
             style={{ aspectRatio: ratioOf(source) }}>
          {isNear ? <SourceCardMedia source={source} … /> : <SourceCardBackdrop … />}
        </div>
      )}
    </div>
  );
}

11. Verification

Unit (Vitest, written first)

  • detectFileKind: .md with an empty type → text; text/html, .csv → null.
  • createSource with .md: the record has text.body and storageKey: null, and no OPFS write. A 2 MB text is rejected.
  • toTextCardTitle: a heading wins; the first sentence is cut at .; **bold** and [link](url) are stripped; whitespace only → fallback.
  • Replace on a text source: image → thumbnail with the kind kept; video → the same; .md → body replaced and thumbnail kept.
  • Replace on an embedded website: video → stays a website with a video thumbnail. This was rejected before.
  • runCompression on a website or text with a video thumbnail reads video metadata, not image metadata.
  • updateSourceText: the body changes and the rest is kept; empty throws; a non-text source throws.
  • Export and import: the full list is in Export & import, including a round-trip test.
  • flipFrame with anchor: 'top' lines up the top edges.
  • SourceTextDocument: <script> shows as text; a remote image makes no request; links get noreferrer.

E2E (Playwright)

  • Drop a .md: the card shows the serif first sentence and its height fits the text.
  • Open: the sheet flies out of the card (check the animation exists). Close: it flies back.
  • Add a video thumbnail in the panel: the card shows an inset video. The same works on an embedded website.
  • Edit, save and reload: the change stays. Dirty + Esc → confirm.

By hand

  • Watch the FLIP for text, embedded and not-embedded sites at normal speed and at 10× slow-down (DevTools animations), in light and dark mode.
  • Check that the inset thumbnail corners are parallel to the card corners.
  • Scroll 300 text cards with video thumbnails: no jank.
  • Drop a .md from Finder and from Windows (empty type).

12. Known gaps after this

  • Search stays name-only. The text is in IndexedDB now, so adding it to search is small later.
  • No way to remove a thumbnail, only to replace it.
  • Files are read as UTF-8; other encodings show broken letters.
  • No “new note” without a file. It is easy on top of edit (B).
