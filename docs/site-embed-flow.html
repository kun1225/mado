Website Source: how it works

You paste a URL. Mado saves it as a source. Later, you see the site inside the app.

1. The big picture

Browser apps/web

  • Asks for the URL
  • Checks the URL shape
  • Calls the API
  • Saves the result
  • Shows the iframe or image

Server apps/api

  • POST /sites/preview reads the site
  • POST /sites/image downloads the OG image
  • Blocks private addresses

Local in the browser

  • IndexedDB: the source record
  • OPFS: the cover image file

The server saves nothing. It only reads the site and answers. All data lives in the user's browser.

2. Add a website: step by step

Then the web app writes the image to OPFS and the record to IndexedDB.

  1. User pastes a URL web WebsiteUrlDialog → createWebsiteSource(). Zod checks: http(s) only, max 2048 chars, no user name or password.
  2. Ask the API for a preview web fetchSitePreview(url) sends POST /api/v1/sites/preview.
  3. Server reads the page safely api safeFetch: blocks private IPs, 8 s timeout, max 5 redirects, 1 MB body.
  4. Server builds the preview api Title, description, favicon, OG image from the HTML. Then chooseEmbed decides the embed mode (see section 3).
  5. Download the OG image web → api fetchSiteImage(ogImage) → POST /sites/image. The browser cannot do this itself because of CORS. The server uses the same safeFetch rules: max 5 MB, only png, jpeg, webp, gif, avif (no SVG). No OG image, or a failed download, is fine: the card shows the site name as text.
  6. Save the source local Cover image → OPFS (key = source id). Record with kind: 'website' and site: {…} → IndexedDB. If the save fails, the image file is deleted.
  7. Show it web SourceDetailViewer picks iframe, image, or a message.

3. Source control: can this site be embedded?

"Source control" here means: the server decides how a site may be shown. It returns one embed.mode.

Mode Meaning iframe sandbox
provider Known site with an official embed link. allow-scripts allow-same-origin allow-forms allow-popups
iframe The site did not forbid framing. allow-scripts allow-forms allow-popups (no same-origin: stricter)
none Cannot be framed. Show an image instead. no iframe

How framing is checked

  • Content-Security-Policy: frame-ancestors must list our app origin. If it does not → csp.
  • X-Frame-Options: DENY or SAMEORIGIN (or two values that disagree) → x-frame-options.
  • CSP is checked first. No rule at all means allowed.

4. What the viewer shows

Case User sees
embed.mode is provider or iframe Live iframe
mode none and we saved a cover image The cover image (from OPFS)
mode none and no image "This website cannot be embedded and has no preview image."
Always "Open original site" link (noopener noreferrer)

5. The data we save

Source {
  kind: 'website',
  url:  preview.finalUrl,            // after redirects
  name: preview.title ?? domain,     // max 120 chars
  site: {
    url, finalUrl, domain, title, description, favicon, ogImage,
    embed: { mode: 'provider'|'iframe', src } | { mode: 'none', reason },
  },
  storageKey: cover ? id : null,        // OPFS file name of the OG image
  width, height, mimeType, sizeBytes    // read from the cover image, or empty
}

Where it lives: record in IndexedDB (sources store), cover image in OPFS under the same id.

6. Safety rules

  • SSRF block: safeFetch uses a guarded DNS lookup. Private and local IPs are refused (400 url-not-allowed).
  • Limits: 8 s timeout, 5 redirects. Page: 1 MB. Image: 5 MB.
  • Image rules: only png, jpeg, webp, gif, avif. No SVG (it can hold scripts). Status must be 2xx.
  • iframe: sandbox, no top navigation, referrerPolicy="no-referrer".
  • Errors: bad URL → 400 invalid-url. Other failures → 500 internal or 502 image-failed.
